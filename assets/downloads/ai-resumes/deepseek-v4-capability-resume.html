1 · Professional Identity

Official identity. DeepSeek — a large language model family developed by DeepSeek (深度求索). In this dossier the subject is the V4 generation, exposed through the DeepSeek API and consumer surfaces. Canonical API identifiers are deepseek-flash (served by DeepSeek-V4.1-Flash-1017) and deepseek-v4-pro (served by DeepSeek-V4-Pro-0813). Legacy IDs deepseek-chat and deepseek-reasoner are deprecated; deepseek-v4-flash and deepseek-v4-flash-vision-exp route to V4.1-Flash for compatibility.

Developer & organisation

DeepSeek (Hangzhou-based AI lab). The V4 family ships with open weights under the MIT licence and an Apache-2.0 inference engine — downloadable, commercially usable, fine-tunable, and privately deployable. This is a structural differentiator against API-only proprietary competitors.

Generation & variants

Two production tiers: Flash (cost/speed/multimodal breadth) and Pro (maximum reasoning and agentic performance). V4.1-Flash-1017 is the smallest model in the new architecture family, with native visual understanding, higher throughput, and a higher capability ceiling. V4-Pro-0813 is the GA release positioned for production agent workloads.

Knowledge limitations

Training data has a cutoff; post-cutoff events require live retrieval and are not independently verified. No persistent memory across conversations unless a product feature explicitly provides it.

2 · Executive Summary

DeepSeek-V4 is a frontier-adjacent, open-weight, exceptionally cost-efficient model family. Its defining property is not benchmark supremacy — it does not hold that — but delivery of roughly 95–100% of frontier coding and reasoning capability at a small fraction of proprietary token prices, with a 1M-token window and MIT-licensed weights.

Where it wins

Cost-per-capability; long-context workloads; SWE-bench Verified 80.6% (V4-Pro); open-weight deployability; OpenAI/Anthropic/Responses API compatibility; MCP ecosystem support.

Where it trails

Absolute frontier on Dtbench (89.8 vs 98.2 leader) and HLE; no native image generation; no native video; vision absent on V4-Pro; brand/ecosystem maturity behind proprietary labs.

Honest positioning. A high-capability, high-value workhorse for coding, agentic automation, research synthesis, and document-heavy workflows — not the absolute best model for every frontier reasoning task, not natively multimodal in generation, and not a substitute for human verification on high-stakes factual or security decisions.

4 · Core Competencies

  1. Long-context reasoning and synthesis. The 1M window is operational, not decorative: whole repositories, multi-hundred-page contracts, full books, and months of transcripts can be held in one inference context.
  2. Software engineering. Generation, refactoring, debugging, test writing, multi-file edits, agentic issue resolution. SWE-bench Verified 80.6% (V4-Pro) is within noise of the best proprietary model.
  3. Agentic tool use. Native function calling, MCP compatibility, Responses API, DeepSeek Harness. Toolathlon-Verified 74.1% indicates strong multi-tool orchestration.
  4. Cost-efficient high-volume inference. Enables workloads that are economically marginal on proprietary frontier pricing.
  5. File-grounded document analysis. PDFs, Office files, images parsed into context; standalone OCR API.
  6. Open-weight deployability. MIT weights allow on-premise, air-gapped, fine-tuned, and commercially redistributed deployment.
  7. Multilingual breadth. Strong EN/ZH; adequate coverage of major European and Asian languages.
  8. Structured output and integration. JSON mode, dual API compatibility, FIM, prefix completion lower integration friction.

6 · Model Specifications

Context and output. 1M input / 384K output for both tiers — roughly 750,000 English words, far beyond Claude Opus 4.5's 200K and GPT-5.2's 400K; at parity with Gemini 3 Pro's 1M.

Thinking control. Low/high/max effort lets one endpoint serve latency-sensitive chat and deep agentic tasks.

API compatibility. OpenAI-format, Anthropic-format, Responses API, JSON, tool calls, prefix completion, FIM. Existing OpenAI or Anthropic SDK code can often be redirected with a base-URL and model-name change.

Open weights. MIT-licensed V4 family weights; Apache-2.0 inference engine. A structural differentiator against API-only proprietary models.

10 · Programming Capabilities

Top-tier by benchmark evidence: SWE-bench Verified 80.6% (V4-Pro) is within noise of Claude Opus 4.5 (80.9%) and above GPT-5.2 Pro (80.0%) on the same snapshot. The 1M window allows an entire mid-sized repository, manifests, tests, and issue history to be loaded at once, reducing retrieval engineering.

Strong: production-quality code in Python, JS/TS, Go, Rust, Java, C++, SQL, shell; multi-file refactors; test writing; stack-trace explanation; API design; common security anti-pattern review; full-stack scaffolds; IaC; migration scripts.

Human review essential: subtle concurrency, performance-critical optimisation, cryptographic code, regulatory logic, and any change verified against live production. Code cannot be executed natively in this session — reasoning about code is not proof it runs.

Vibe coding. Natural-language brief → working scaffold (frontend, backend, schema, API contracts) is fast. The limiting factor is verification and environment setup, not generation.

11 · Automation Capabilities

Automation runs through tool calling, MCP, and agent harnesses. Official integrations include Codex and DeepSeek Harness; the Responses API is adapted for Codex.

Realistic pipelines

Document processing; code maintenance bots; research assistants; support triage; invoice reconciliation.

Hard guardrails

No irreversible financial transactions, no unreviewed production deploys, no regulated personal data without compliance review, no over-broad credentials.

12 · AI Agent Development

DeepSeek is a credible agent foundation because it combines four properties agents need: long context, reliable tool calling, thinking-effort control, and low token cost. A long-running agent making hundreds of tool calls is economically painful on $15/M-output proprietary models; affordable here.

  • ReAct single agent with scratchpad reasoning and tool calls.
  • Plan-and-execute decomposition with re-planning on failure.
  • Multi-agent supervisor coordinating specialised sub-agents (runtime is external).
  • RAG agent using Search/Fetch/OCR as tools.
  • Coding agent via IDE/CI integration through MCP or Responses API.

Constraints: no native persistent runtime, long-term memory store, or credential vault — those are architectural components the developer supplies. Reliability degrades on ambiguous tool errors, real-world side effects, and low-value tool-output flooding.

13 · Research Capabilities

Native: synthesis, comparison, critique, structured writing over supplied sources. Live: depends on search/URL tools; supports multi-step deep-thinking search with citations.

Weaknesses: citation hallucination without grounding, misreading ambiguous sources, no paywalled access without credentials, no guarantee of source authority, no independent fact-check of long documents. Citation verification is a human responsibility in high-stakes research.

Honest positioning

DeepSeek is not best for native image generation, video understanding, or the hardest composite reasoning benchmarks. It is the best value proposition among frontier-capable models, the strongest open-weight option, and competitive on coding and agentic tasks. Economic meaning. A workload costing $15 per million output tokens on a premium proprietary model costs $1.20–$3.96 on DeepSeek V4 depending on tier and time. For high-volume agentic workloads consuming hundreds of thousands of tokens across tool calls, this is the difference between a viable product and an unviable one. 18 · Strengths

  1. Exceptional cost-efficiency at frontier-adjacent capability.
  2. 1M-token context with 384K output — a genuine workflow transformer.
  3. Open-weight MIT licence, rare at this capability level.
  4. Strong coding and agentic performance, benchmark-verified.
  5. Triple API compatibility (OpenAI, Anthropic, Responses) lowers switching costs.
  6. MCP ecosystem support integrates with dominant agent tooling.
  7. Multimodal input on Flash (vision + files + OCR).
  8. Thinking-effort control: one model, multiple cost/latency profiles.
  9. Broad language coverage, especially EN/ZH.

19 · Weaknesses

  1. Not the absolute frontier on the hardest composite reasoning benchmarks (Dtbench, HLE).
  2. No native image generation; no native video understanding.
  3. Vision unavailable on V4-Pro — only on Flash.
  4. Knowledge cutoff limits unaided recall of recent events.
  5. Non-zero hallucination risk, especially niche facts and citations.
  6. Brand and ecosystem maturity trail OpenAI, Anthropic, Google in enterprise tooling.
  7. Naming volatility (deprecated IDs, routed legacy names) creates maintenance overhead.
  8. Real-time voice is API-based, not a polished native conversational mode.
  9. Documentation and benchmark disclosure less comprehensive than proprietary competitors.

20 · Technical Limitations

  • Cannot natively execute code, browse authenticated sites, or access private databases without tools and credentials.
  • Cannot generate images or video.
  • Cannot guarantee factual accuracy — output is probabilistic text.
  • No memory across conversations by default.
  • Cannot independently verify cited benchmarks; relies on published sources.
  • Cannot produce a compiled PDF binary natively in a chat session.
  • Performance degrades with ambiguous prompts, contradictory context, long tool-output chains, and tasks requiring real-world side effects.
  • Cannot provide licensed legal, medical, or financial advice.

21 · Security & Privacy Considerations

  • Data handling: API data subject to DeepSeek terms; self-hosted weights give full sovereignty.
  • Tool permissions: least-privilege credentials and scoped tokens.
  • Prompt injection: retrieved pages/documents can carry adversarial instructions — treat retrieved content as untrusted.
  • Sensitive data: no secrets, credentials, or regulated personal data without an appropriate DPA.
  • Output safety: enable safety-check parameter for public-facing apps; comply with local AI labelling/registration.
  • Audit logging: log tool name, input, output, timestamp for incident review.

22 · Future Development Opportunities

The trajectory is clear: investment in agentic capability, multimodal understanding, and cost-performance optimisation. V4.1-Flash explicitly targeted agent benchmarks (Terminal-Bench, DeepSWE, AutomationBench, Agents' Last Exam) and reduced runtime and output length for a better performance–cost Pareto point. Likely directions: stronger native tool orchestration, broader multimodal input, improved hallucination calibration, deeper MCP/agent-framework integration. Native image generation remains a gap the Janus research line could eventually close — but it is not a current product capability and should not be assumed.

Evaluation methodology

Scores derive from three inputs weighted equally: (1) published benchmark performance relative to the best available model; (2) official feature/specification disclosure; (3) self-observed operational behaviour. Scores are ordinal judgements, not precise measurements; reasonable auditors could differ by ±0.5. No score is based on marketing claims.
