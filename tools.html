Capability resumes

Seven AI systems audited themselves.

I asked seven assistants the same thing: write your own capability resume — what you can do, what you cannot, what the evidence is, what you cost. These are the documents they returned, unchanged. Each one is written by the system it describes, so read them as claims with a source attached, not as test results. Five of the seven grade their own evidence; two do not.

Read them together, not one at a time. The scorecards are on four different scales and measure four different things — capability, evaluator confidence, environment access. None of them can be ranked against another. What does compare is price, context window, licence and the specific benchmark each maker chose to publish.

Read a number like this, or do not read it at all

Leaderboard numbers move when the harness, the checkpoint or the reasoning effort changes. Kimi K3.1 Pro's Terminal-Bench 2.1 reads 88.3 on Moonshot's card and 85.0 on Meta's. That is the same model, the same benchmark, three points apart. A one-point gap is noise.

So every number here carries its benchmark version and who measured it, and no chart blends two harnesses to make a nicer shape. Where a maker only published some of the numbers, the cell says so rather than filling the gap with a guess.

Two things no leaderboard shows: whether a model answers the same way twice, and whether it will invent an answer rather than admit it does not know. Those are tests 3 and 10 below, and the only way to get them is to run the model on your own work.

Benchmarks

Four charts, four questions.

Who is smartest. What smart costs. How fast it talks. How much it actually knows. Each chart is one source at one version, so the bars inside it are comparable and the bars between charts are not.

What none of these charts can tell you. Whether it answers the same way twice. Whether it says “I don't know” when it doesn't. Whether it keeps its Hindi when the question is in Hinglish. Whether it loses the thread four steps into a tool loop. Those are the four things that decide whether a model survives a working week, and they are all measured by hand, on your own repository. That is the table below.

The battery

Twelve tests, the same order every time.

This is the benchmark that counts, because it is the only one measured on your work. Run them in this order — a model that fails the fit test never gets to the interesting ones.

01

Fit

Weight size in GB, quantisation, KV cache per token. Try it on the machine you actually want to run it on.

Record GB, quant, time to first token, tok/s

02

Licence

Read the LICENSE file on the model card. MIT and Apache ship. The maker's own licence gets read first.

Record Licence name and whether commercial use is allowed

03

Repeatability

Run the same prompt three times at default temperature.

Record Do the three answers agree? Yes or no

04

Your own benchmark

Ten questions whose answers you already know — your repo's CSS bug, the file count, the Netlify config.

Record Pass@1, out of ten. This is the only number that is yours

05

Contamination

Ask something made today, that cannot be in any training set.

Record Right or wrong, and whether it hedged or went straight at it

06

Tokens per task

Finish one real job, then count total input plus output tokens.

Record Tokens per task, and what those tokens cost

07

Tool calling

A five-step loop on a real repo: read, edit, run tests, fix, report.

Record How many steps completed, and where the thread was lost

08

Long context

Hide a fact at 100K, then at 800K. Ask for it back.

Record How deep it still answers correctly

09

Hindi and Hinglish

The same instruction in Hindi, in Hinglish, and in English.

Record Does it stay in the language? Does the tone survive?

10

Honesty

A question it cannot possibly know — a private file, a number that does not exist.

Record “I don't know”, or a confident invention

11

Refusal

One prompt that should be refused, one harmless prompt that should not be.

Record Both handled correctly?

12

Speed

Time to first token, plus output tok/s, on the tier you will use every day.

Record Seconds (TTFT) and tok/s

Where to look next

Ten places I check before I download anything.

  1. Hugging Face — trending — The newest open-weight models, with downloads and likes What just landed — the first stop
  2. OpenWeightsBench — 228 models, 270 questions, 13 categories, all on the same battery and code-checked. Has a hardware picker Choosing a model that has to run on your machine
  3. Artificial Analysis — The AA Intelligence Index, run by them, not the vendors. The open-weights page is separate Comparing real capability
  4. LMArena — Human votes, text and code arena Which model people actually prefer — use the code arena for coding
  5. LMSA leaderboard — AA plus arena plus price plus context, in one table Building a shortlist at a glance
  6. ModelCap — open weights — 223 open models with licence and price Filtering by what the licence allows
  7. OpenRouter — free models — Everything going for $0, ranked by usage Trying a model with no money and no GPU
  8. Ollama library — One command per model: ollama run <model> The easiest way to run something locally
  9. LM Studio — A GUI for local models on Mac (MLX) and Windows When you would rather not touch a terminal
  10. AIMap — free open-weight — 85 free open-weight models, verified The whole free list in one place
One thing to carry away. Leaderboard numbers move when the harness and the checkpoint change. Write the benchmark version and who measured it next to every number you keep, and treat a one-point gap as noise. A model that is two points behind and ten times cheaper is usually the better model for the work you actually have.
